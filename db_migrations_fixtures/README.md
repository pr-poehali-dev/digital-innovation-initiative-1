# Политика: сценарные тестовые данные вне db_migrations

`db_migrations/` предназначена ТОЛЬКО для изменений схемы (CREATE/ALTER TABLE,
индексы, constraints) и по-настоящему постоянных справочников. Она
воспроизводится forward-only на любом окружении, включая чистое развёртывание
с нуля — поэтому любая запись, ссылающаяся на конкретный ID, созданный вручную
через API в одной конкретной сессии проверки, рано или поздно ломает чистое
развёртывание (см. историю правок V0442, V0448, V0445/V0446).

## Правило с этого момента

Одноразовые сценарные проверки (создание тестового проекта/задачи/сессии для
ручной или API-проверки функциональности в рамках диалога с пользователем)
выполняются:

1. через штатные API backend-функций (`save_project`, `save_task`, ...) —
   не через прямые SQL-миграции;
2. через `perform_sql_query`/точечные `migrate_db` только для временного
   `exec_cabinet_access` тестового пользователя и его последующей очистки —
   без постоянного следа в `db_migrations/`;
3. по завершении проверки — тестовые объекты архивируются и помечаются
   `is_test_data = true` через отдельный `migrate_db` вызов, а НЕ через
   создание новой версии в основной цепочке схемы.

Эта папка (`db_migrations_fixtures/`) зарезервирована для будущих
воспроизводимых наборов демо-данных (если такие понадобятся) — она НЕ
применяется автоматически инструментом миграций и не участвует в forward-only
цепочке версий `db_migrations/V####__*.sql`.
