## 2. Уточнение формулировки о «висячих» ссылках

Принимаю ограничение. Прежняя формулировка «висячие
использования невозможны» была **чрезмерно широкой**.

### 2.1. Корректная формулировка

> В рамках ссылочной целостности базы невозможно сохранить
> ссылку на отсутствующую физическую запись.

### 2.2. Что внешний ключ НЕ гарантирует

| Ситуация | Внешний ключ защищает |
|---|---|
| Ссылка на физически удалённую запись | **Да** |
| Ссылка на **архивированную** запись | **Нет** |
| Ссылка на запись **отменённого** документа | **Нет** |
| Ссылка на **логически удалённую** запись | **Нет** |

### 2.3. Правила допустимости — определяются отдельно

| Ситуация | Предлагаемое правило | Статус |
|---|---|---|
| Целевая запись архивирована | Использование помечается неактуальным, не удаляется | **Требует отдельного согласования** |
| Документ отменён | Предупреждение по всем использованиям | Требует согласования |
| Документ заменён | Предложение перепривязки к новому документу | Требует согласования |
| Истёк срок применимости | Использование считается неактуальным | Требует согласования |

**В MVP эти правила не специфицированы.** Выношу отдельным
вопросом.

### 2.4. Матрица допустимых сочетаний

| Свойство | Состояние |
|---|---|
| Зафиксирована в концептуальной спецификации | **Да**, `rev2-10` разд. 2.4 |
| Защищена ограничениями базы | **Не сейчас** — желательно в будущем |
| Обоснование | Реализация не разрешена; для концептуальной модели достаточно точной фиксации |

### 2.5. Девятая целевая сущность

Добавление девятого типа цели — **изменение схемы**, требует
отдельного согласования. Набор из восьми целей закрыт.

## 3. Восемь статусов — проверка на смысловое пересечение

Перечисляю непосредственно, как вы потребовали.

| № | Код | Название | Отличительный признак — что делает статус уникальным |
|---|---|---|---|
| 1 | `ai_draft` | AI-черновик | Сформировано машиной, **человек не подтверждал даже авторство** |
| 2 | `user_draft` | Черновик пользователя | Внесено человеком, **на проверку не отправлялось** |
| 3 | `in_review` | На проверке | Отправлено на проверку, **решение проверяющего отсутствует** |
| 4 | `confirmed` | Подтверждено владельцем | Проверено **независимым** уполномоченным, содержание достоверно |
| 5 | `approved` | Утверждено | Помимо достоверности **придана обязательность** для исполнения |
| 6 | `accepted_by_exception` | Принято по исключению | Используется в работе, но **независимая проверка не выполнялась** |
| 7 | `needs_update` | Требует актуализации | Ранее проверялось, но **утратило актуальность** |
| 8 | `archived` | Архив | **Выведено из обращения**, история сохранена |

### 3.1. Проверка попарного пересечения

| Пара, вызывающая вопрос | Различие |
|---|---|
| `ai_draft` / `user_draft` | Автор: машина или человек |
| `user_draft` / `in_review` | Факт отправки на проверку |
| `in_review` / `confirmed` | Наличие решения проверяющего |
| `confirmed` / `approved` | Достоверность против обязательности |
| **`confirmed` / `accepted_by_exception`** | **Наличие независимой проверки** — ключевое различие |
| `accepted_by_exception` / `in_review` | Используется в работе или ожидает решения |
| `needs_update` / `user_draft` | Было проверено ранее или никогда |
| `archived` / `needs_update` | Выведено из обращения или подлежит обновлению |

**Смысловых пересечений не обнаружено.**

### 3.2. `accepted_by_exception` не эквивалентен `confirmed`

| Требование | Реализация |
|---|---|
| Явно отображается как принятая по исключению | Отдельная пометка в интерфейсе и экспорте |
| **Не учитывается как независимо подтверждённая** | В отчётах считается отдельно от `confirmed` |
| Основание обязательно | Текстовое поле, без него статус не устанавливается |
| Автор исключения обязателен | Фиксируется |
| Срок действия обязателен | Дата окончания |
| Действие журналируется | `mgmt_audit_log` |
| Содержательное изменение прекращает исключение | Переход в `needs_update` |
| Ретроспективная проверка при появлении проверяющего | Отдельная очередь контроля |
| Результат ретроспективной проверки фиксируется | Отдельная запись в журнале |
| Администратор не применяет исключение | Прав нет по матрице |

### 3.3. Просроченное исключение

**Девятый статус не добавляется.** Просрочка — **вычисляемый
признак**.

| Свойство | Реализация |
|---|---|
| Определение | Срок действия исключения меньше текущей даты |
| Видимость пользователю | Явная пометка «срок исключения истёк» |
| Молчаливое продолжение действия | **Исключено** — запись отображается как просроченная |
| Попадание в очередь контроля | Автоматическое |
| Учёт в отчётах | Отдельно от действующих исключений |

### 3.4. Исключение к собственной записи

| Правило | Реализация |
|---|---|
| Допустимость | **Только как аварийная процедура** |
| Очередь последующего контроля | **Обязательна**, запись остаётся в ней |
| Представление пользователям | **Не показывается** как независимо подтверждённая |
| Снятие из очереди | Только после проверки другим уполномоченным лицом |

### 7.2. ТЕКСТ ЗАПРОСА ДЛЯ ПОДАЧИ

**Тема:** Создание изолированной тестовой среды для проверки
безопасности

**Цель:**

> Интеграционно подтвердить, что после отключения параметра
> `audit_mode` ни одна авторизованная роль не получает архивные
> поля, флаги или значения, а архивные данные в хранилище
> не изменяются.

**Обоснование:** проверка в рабочей среде невозможна —
недопустимо создавать сессии в рабочей системе, заводить
синтетические учётные записи в рабочей базе и копировать
архивные данные.

**Требования к среде:**

| № | Требование |
|---|---|
| 1 | Отдельный URL либо отдельный проект |
| 2 | Отдельная тестовая база данных |
| 3 | Только синтетические данные |
| 4 | Отсутствие копии рабочего архива |
| 5 | Тестовые учётные записи для четырёх ролей: владелец, администратор, редактор, наблюдатель |
| 6 | Возможность создавать и удалять тестовые сессии |
| 7 | Журналирование без архивных и персональных значений |
| 8 | Гарантированный запрет обращения тестов к рабочей среде |
| 9 | Процедура очистки данных после прогона |
| 10 | Возможность удалить среду после завершения проверки |

**Объём проверки:** 12 сценариев, 27 прогонов. Время
выполнения — менее одной минуты.

**Срок использования:** разовая проверка, среда может быть
удалена сразу после получения результата.

**Что не требуется:** доступ к рабочим данным, копирование
рабочей базы, постоянное существование среды.
