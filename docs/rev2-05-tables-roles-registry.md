### 6.2. Составной внешний ключ — концептуально

```
ref_dictionary_type (вид справочника)
  ├─ код вида (первичный ключ, неизменяемый)
  └─ признак системного вида

ref_dictionary_value (значение)
  ├─ код вида ──────► внешний ключ на ref_dictionary_type
  ├─ код значения
  ├─ UNIQUE (код вида, код значения)
  └─ признак системного значения

Ссылающаяся сущность, например initiative:
  ├─ status_dict_type = 'initiative_status'  ← ФИКСИРОВАННОЕ значение
  ├─ status_code
  └─ FOREIGN KEY (status_dict_type, status_code)
       ──► ref_dictionary_value (код вида, код значения)
```

Ссылка на значение чужого вида **невозможна на уровне базы**:
поле вида в ссылающейся таблице зафиксировано ограничением
`CHECK`, а составной внешний ключ проверяет пару целиком.
Прикладная валидация не требуется.

## 7. Роли доступа: разделение на три плоскости

Ваше замечание принято: количество ролей определяется различиями
в правах, а не организационными названиями. Восемь ролей
из прошлой редакции **пересматриваю**.

### 7.1. Плоскость 1. Системные роли доступа — 4

Определяют **технические права** в системе.

| Код | Название | Область действия |
|---|---|---|
| `sys_admin` | Системный администратор | Вся система, без содержательных прав |
| `sys_manager` | Управляющий кабинетом | Весь портфель кабинета |
| `sys_editor` | Редактор | Инициативы, где назначена бизнес-роль |
| `sys_viewer` | Наблюдатель | Только просмотр разрешённого |

**Обоснование сокращения до 4:** роли различаются **набором прав**,
а не названием должности.

### 7.2. Плоскость 2. Бизнес-роли в инициативе

**Не являются ролями доступа.** Хранятся в `role_template`,
настраиваются пользователем: куратор, владелец инициативы,
руководитель инициативы, функциональный заказчик и другие.

**Критическое правило:** бизнес-роль **не даёт автоматически**
системных прав. Владелец инициативы получает права `sys_editor`
в рамках своей инициативы — не более. Административные полномочия
не наследуются от организационного названия.

### 7.3. Плоскость 3. Субъекты принятия решений

**Не являются ролями доступа.** Определяются в
`decision_participation`: кто принимает окончательное решение,
кто согласовывает. Право принять решение в модели **не равно**
праву изменить запись в системе.

### 7.4. Матрица прав системных ролей

**+** полный · **±** в рамках назначенных инициатив · **−** нет

| Право | `sys_admin` | `sys_manager` | `sys_editor` | `sys_viewer` |
|---|---|---|---|---|
| **Область действия** | Вся система | Портфель кабинета | Свои инициативы | Разрешённое |
| Просмотр | + | + | ± | ± |
| Создание | + | + | ± | − |
| Редактирование | + | + | ± | − |
| Подтверждение | **−** | + | ± | − |
| Утверждение | **−** | + | **−** | − |
| Архивирование | + | + | ± | − |
| Экспорт | + | + | ± | − |
| Просмотр истории | + | + | ± | − |
| Просмотр источников | + | + | ± | ± |
| Просмотр конфиденциальных полей | **−** | + | ± | **−** |
| Управление доступом | + | + | − | − |
| Управление справочниками | + | + | − | − |
| Административное исключение зависимости | **−** | + | − | − |

### 7.5. Обоснование каждой роли

| Роль | Чем отличается от других |
|---|---|
| `sys_admin` | Единственная с полным техническим доступом, но **без** подтверждения, утверждения и конфиденциальных полей |
| `sys_manager` | Единственная с правом утверждения и полным доступом к конфиденциальным полям |
| `sys_editor` | Ограничена своими инициативами; **без** утверждения и управления доступом |
| `sys_viewer` | Только чтение; **без** конфиденциальных полей |

**Ни одна пара ролей не имеет одинакового набора прав** — проверено
по всем 13 строкам матрицы.

### 7.6. Что изменилось относительно прошлой редакции

| Было (8 ролей) | Стало |
|---|---|
| `administrator` | `sys_admin` |
| `cabinet_head` | `sys_manager` |
| `group_head` | `sys_manager` или `sys_editor` — по области действия |
| `group_secretary` | `sys_editor` + бизнес-роль «секретарь» |
| `initiative_owner` | `sys_editor` + бизнес-роль «владелец» |
| `initiative_manager` | `sys_editor` + бизнес-роль «руководитель» |
| `participant` | `sys_editor` с ограниченной областью |
| `observer` | `sys_viewer` |

**Итог: 4 системные роли** вместо 8. Организационные названия
перенесены в бизнес-роли, которые настраиваются без изменения кода.

**До согласования этой матрицы новые системные роли не создаю,**
используются существующие права проекта.

## 8. Уточнение показателей матриц

Ваше замечание принято: «влияние» также может быть субъективной
оценкой человека. Перехожу к подтверждаемым основаниям.

### 8.1. Показатель «Формальное участие»

Вычисляется из **фактических записей**, не оценивается человеком.

| Основание | Источник данных | Вес |
|---|---|---|
| Право принять окончательное решение | `decision_participation`, вид `decides` | Высший |
| Обязательность согласования | `decision_participation`, вид `approves`, признак обязательности | Высокий |
| Право блокирования | Обязательное согласование при блокирующей зависимости | Высокий |
| Владение необходимым ресурсом или информацией | `decision_participation`, вид `provides_info` | Средний |
| Роль в решении | Наличие любого вида участия | Базовый |
| Документированный уровень участия | `role_assignment` с основанием | Базовый |

**Правило расчёта:** показатель = максимальный вес среди всех
оснований участника в данной инициативе. **Не задаётся вручную.**

### 8.2. Показатель «Фактическая вовлечённость»

| Основание | Источник |
|---|---|
| Число решений с участием | `decision_participation` |
| Число зафиксированных требований | `stakeholder` |
| Наличие актуальных записей | Дата последней фиксации |

### 8.3. Три матрицы — уточнённые названия

| № | Матрица | Ось X | Ось Y | Объект |
|---|---|---|---|---|
| 1 | Формальное участие × фактическая вовлечённость | Вовлечённость | Формальное участие | Стейкхолдеры |
| 2 | Формальное участие × наличие нерешённых вопросов | Число открытых вопросов | Формальное участие | Стейкхолдеры |
| 3 | Критичность решения × готовность решения | Готовность | Критичность | **Решения, не лица** |

**Принято ваше уточнение:** третья матрица относится к решениям.
Привязка к конкретным лицам **не выполняется**.

### 8.4. Обязательные атрибуты каждого показателя

| Атрибут | Реализация |
|---|---|
| Определение | Текст в описании показателя |
| Источник | Ссылка на записи, из которых вычислен |
| Дата | Дата последнего пересчёта |
| Автор фиксации | Для ручных данных — кто внёс |
| Правила расчёта | Отображаются по запросу пользователя |
| Статус достоверности | Единый справочник статусов |
| **«Нет данных»** | **Отдельное состояние**, не заменяется нулём или предположением |

### 8.5. Запрещённые показатели

Матрицы на реальных лицах **не содержат**: отношение · лояльность
· сопротивление · опасения · любое AI-профилирование.

Соответствующие поля в модели отсутствуют — исключены на уровне
структуры данных, а не интерфейса.
