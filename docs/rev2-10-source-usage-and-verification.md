## 2. Модель `source_usage` — явные внешние ключи

Полиморфная ссылка **отменена** по вашему решению.
Расширение до 25 таблиц не выполняется. Реестр остаётся **17**.

### 2.1. Принцип модели

Одна таблица `source_usage` с **явными необязательными внешними
ключами** на каждую допустимую целевую сущность.

```
source_usage
├─ source_document_id      → FK на source_document  [ОБЯЗАТЕЛЬНО]
├─ usage_type              → классификатор типа использования
│
├─ ЦЕЛЕВЫЕ ССЫЛКИ (заполнена РОВНО ОДНА):
│   ├─ role_assignment_id        → FK  [NULL]
│   ├─ decision_participation_id → FK  [NULL]
│   ├─ decision_instance_id      → FK  [NULL]
│   ├─ decision_dependency_id    → FK  [NULL]
│   ├─ stakeholder_id            → FK  [NULL]
│   ├─ initiative_id             → FK  [NULL]
│   ├─ collegial_body_id         → FK  [NULL]
│   └─ collegial_body_member_id  → FK  [NULL]
│
├─ CHECK: ровно одна ссылка не NULL
├─ fragment_ref            → пункт, раздел, фрагмент
├─ applicable_from / applicable_to
├─ comment
└─ recorded_at / recorded_by
```

## 3. Шесть сущностей независимой проверки

Перечисляю непосредственно, как вы потребовали.

### 3.1. `role_assignment` — Назначение роли

| Параметр | Значение |
|---|---|
| **Что подтверждается** | Правомерность наделения лица или органа ролью в инициативе |
| **Содержательное изменение** | Смена субъекта (лицо, подразделение, орган); смена роли; изменение пределов полномочий; изменение периода действия; смена основания |
| **Сбрасывает подтверждение** | Любое из перечисленного → статус `needs_update` |
| **Кто подтверждает** | Управляющий кабинетом; редактор — если не он создал или изменил запись |
| **При отсутствии проверяющего** | Запись **не считается независимо подтверждённой**, остаётся в статусе «на проверке» |

### 3.2. `decision_participation` — Участие роли в решении

| Параметр | Значение |
|---|---|
| **Что подтверждается** | Правомерность полномочия роли участвовать в решении, особенно вид «принимает окончательное решение» |
| **Содержательное изменение** | Смена вида участия; смена роли; изменение обязательности; изменение основания полномочия; изменение условия эскалации |
| **Сбрасывает подтверждение** | Любое из перечисленного |
| **Кто подтверждает** | Управляющий кабинетом; редактор — при соблюдении независимости |
| **При отсутствии проверяющего** | Не считается независимо подтверждённой |

### 3.3. `decision_instance` — Экземпляр решения

| Параметр | Значение |
|---|---|
| **Что подтверждается** | Факт и содержание принятого управленческого решения |
| **Содержательное изменение** | Изменение формулировки вопроса; изменение принятого решения; смена принявшего субъекта; изменение даты принятия; изменение документа-основания; изменение статуса на «принято» |
| **Сбрасывает подтверждение** | Любое из перечисленного |
| **Кто подтверждает** | Управляющий кабинетом; редактор — если не он вносил решение |
| **При отсутствии проверяющего** | Не считается независимо подтверждённой |

### 3.4. `collegial_body` — Коллегиальный орган

| Параметр | Значение |
|---|---|
| **Что подтверждается** | Правоспособность органа: полномочия, кворум, порядок голосования |
| **Содержательное изменение** | Изменение полномочий; изменение кворума; изменение порядка голосования; изменение необходимого большинства; смена председателя или секретаря; изменение основания создания |
| **Сбрасывает подтверждение** | Любое из перечисленного |
| **Кто подтверждает** | **Только управляющий кабинетом** — затрагивает правоспособность |
| **При отсутствии проверяющего** | Не считается независимо подтверждённой |

### 3.5. `collegial_body_member` — Участник коллегиального органа

| Параметр | Значение |
|---|---|
| **Что подтверждается** | Правомерность включения в состав и наличие права голоса |
| **Содержательное изменение** | Смена лица или организационной позиции; изменение роли в органе; **изменение права голоса**; изменение периода полномочий; смена основания включения |
| **Сбрасывает подтверждение** | Любое из перечисленного |
| **Кто подтверждает** | **Только управляющий кабинетом** — влияет на правоспособность состава |
| **При отсутствии проверяющего** | Не считается независимо подтверждённой |

### 3.6. `source_document` — Карточка документа

| Параметр | Значение |
|---|---|
| **Что подтверждается** | Достоверность реквизитов документа, служащего основанием |
| **Содержательное изменение** | Изменение типа, наименования, номера, даты, издателя; изменение срока действия; изменение ссылки на документ; **изменение состояния** (действует, отменён, заменён) |
| **Сбрасывает подтверждение** | Любое из перечисленного; **дополнительно** формируется предупреждение по всем использованиям этого документа |
| **Кто подтверждает** | Управляющий кабинетом; редактор — при соблюдении независимости |
| **При отсутствии проверяющего** | Не считается независимо подтверждённой |

### 3.7. Что НЕ считается содержательным изменением

Ни в одной из шести сущностей **не сбрасывают** подтверждение:

исправление опечатки в описании или комментарии · изменение
порядка сортировки · добавление или изменение комментария ·
обновление технических полей (`updated_at`) · изменение
отображаемого наименования без изменения кода · перемещение
записи между представлениями интерфейса.

**Технические изменения, не влияющие на смысл записи,
подтверждение не сбрасывают.**

## 4. Статус «принято по исключению»

### 4.1. Отдельный статус

Аварийное исключение **не называется обычным подтверждением**.

**Новый статус жизненного цикла: `accepted_by_exception` —
«Принято по исключению».**

Единый справочник статусов расширяется до **8 значений**:

| Код | Название |
|---|---|
| `ai_draft` | AI-черновик |
| `user_draft` | Черновик пользователя |
| `in_review` | На проверке |
| `confirmed` | Подтверждено владельцем |
| `approved` | Утверждено |
| **`accepted_by_exception`** | **Принято по исключению** |
| `needs_update` | Требует актуализации |
| `archived` | Архив |

### 4.2. Правила применения исключения

| Правило | Реализация |
|---|---|
| Кто может применить | **Только управляющий кабинетом** |
| Администратор | **Не может** — техническая роль не даёт содержательного подтверждения |
| Редактор | Не может |
| Обязательное основание | Текстовое обоснование, обязательно |
| Обязательный срок | Дата, до которой действует исключение |
| Автор | Фиксируется |
| Запись в журнале | Обязательна |

### 4.3. Исключение к собственной записи

| Ситуация | Результат |
|---|---|
| Управляющий кабинетом применяет исключение к **чужой** записи | Допустимо |
| Управляющий кабинетом применяет исключение к **собственной** записи | Допустимо, но **с обязательным последующим контролем** другим уполномоченным лицом |
| Признак записи | Помечается как требующая ретроспективной проверки |

### 4.4. Ретроспективная проверка

| Событие | Действие |
|---|---|
| Появление второго уполномоченного проверяющего | Все записи со статусом `accepted_by_exception` **подлежат ретроспективной проверке** |
| Истечение срока исключения | Предупреждение, запись переходит в `needs_update` |
| Результат ретроспективной проверки | Переход в `confirmed` либо в `needs_update` |
| Отображение | Признак «принято по исключению» виден в интерфейсе и при экспорте |

### 4.5. Отсутствие второго уполномоченного

> **Если второго уполномоченного пользователя нет, запись
> не считается независимо подтверждённой.**

Доступные варианты: оставить в статусе «на проверке» **либо**
применить исключение с основанием, сроком и последующей
ретроспективной проверкой.

**Автоматического перевода в `confirmed` не происходит
ни при каких условиях.**

## 5. Уточнение классификаторов

### 5.1. Переименование

| Было | Стало |
|---|---|
| «Уровень вовлечённости» | **«Состояние участия»** (`participation_state`) |
| «Состояние лица» | **«Состояние записи лица»** (`person_record_state`) |

Названия приняты по вашей рекомендации — точнее отражают
содержание и не провоцируют субъективную оценку.

### 5.2. «Состояние участия» — требования к каждому состоянию

| Требование | Реализация |
|---|---|
| Проверяемый факт, не оценка | Каждое состояние выводится из записи в системе |
| Источник или событие-подтверждение | Обязательная ссылка на запись либо `source_usage` |
| Дата фиксации | Обязательное поле |
| Состояние «данные отсутствуют» | Отдельное значение `no_data` |
| **Не вычисляется ИИ** | Устанавливается только человеком или детерминированным правилом |
| Не используется для вывода о лояльности, отношении, поведении | Запрет закреплён в модели: соответствующих полей нет |

**Восемь состояний с основаниями:**

| Код | Состояние | Основание фиксации |
|---|---|---|
| `not_required` | Участие не требуется | **См. 5.3** |
| `invitation_not_sent` | Приглашение не направлено | Отсутствие записи о направлении |
| `invitation_sent` | Приглашение направлено | Запись с датой направления |
| `participation_confirmed` | Участие подтверждено | Запись с датой подтверждения |
| `materials_provided` | Материалы предоставлены | Ссылка на `source_usage` |
| `remarks_received` | Замечания получены | Зафиксированные замечания с датой |
| `decision_pending` | Решение ожидается | Незакрытый `decision_instance` |
| `no_data` | Данные отсутствуют | Явное состояние, **не заменяется предположением** |

### 5.3. Основание состояния «участие не требуется»

**Не может быть неподтверждённым ручным мнением.**

| Допустимое основание | Проверка |
|---|---|
| Правило процесса | Ссылка на `source_usage` с типом `information_source` |
| Управленческое решение | Ссылка на `decision_instance` |
| Отсутствие назначенной роли | Проверяется автоматически: нет записи в `role_assignment` и в `decision_participation` |

При отсутствии любого из трёх оснований состояние
**не может быть установлено** — применяется `no_data`.

### 5.4. «Состояние записи лица» — фиксация ограничений

| Значение | Что означает | Что НЕ означает |
|---|---|---|
| `active` | Запись используется | — |
| `archived` | Запись выведена из обращения | **Не означает** увольнение или прекращение полномочий |
| `depersonalized` | Идентифицирующие сведения удалены | **Не означает** удаление всех связанных фактов |

**Дополнительные правила:**

| Правило | Фиксация |
|---|---|
| Кадровые события не выводятся из этих значений | Система не интерпретирует состояние записи как кадровое событие |
| Переход в `depersonalized` журналируется | Обязательная запись в `mgmt_audit_log` |
| Требования к фактическому обезличиванию | **Определяются отдельно**, в MVP не специфицированы |
| Связанные факты при обезличивании | Сохраняются: назначения ролей, участие в решениях остаются |

## 7. Предохранитель тестов — переработан

Принято ваше требование: **положительное подтверждение**
тестовой среды вместо списка запрещённых адресов.

```python
# ПРОЕКТ. conftest.py — НЕ СОЗДАН

def pytest_configure(config):
    """Предохранитель. Выполняется ДО первого сетевого запроса."""
    # 1. Явный признак тестовой среды — ОБЯЗАТЕЛЕН
    if os.environ.get("TEST_ENV_CONFIRMED") != "isolated-test-env":
        pytest.exit(
            "ОСТАНОВЛЕНО: отсутствует явное подтверждение тестовой "
            "среды (TEST_ENV_CONFIRMED). Запуск запрещён.",
            returncode=2)

    # 2. Обязательный маркер тестового проекта
    if os.environ.get("TEST_PROJECT_ID") != "999001":
        pytest.exit("ОСТАНОВЛЕНО: не задан синтетический проект.",
                    returncode=2)

    # 3. Проверка, что база — тестовая
    if "test" not in os.environ.get("TEST_DB_DSN", "").lower():
        pytest.exit("ОСТАНОВЛЕНО: база не помечена как тестовая.",
                    returncode=2)
```

| Список запрещённых адресов | **Не используется** как единственный механизм |
| Момент срабатывания | `pytest_configure` — **до первого сетевого запроса** |
