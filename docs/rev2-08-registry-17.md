## 3. Обоснование полиморфной ссылки

Требуется отдельное обоснование — принимаю замечание.

### 3.1. Суть проблемы

`source_usage` ссылается на записи **девяти разных таблиц**:
`role_assignment`, `decision_participation`, `decision_instance`,
`stakeholder`, `initiative`, `collegial_body`,
`collegial_body_member`, `decision_dependency`, `person`.

### 3.2. Сравнение вариантов

| Критерий | Полиморфная ссылка (тип + идентификатор) | Явные таблицы связей |
|---|---|---|
| Количество таблиц | **1** | **9** |
| Ссылочная целостность на уровне БД | **Отсутствует** — внешний ключ невозможен | **Полная** |
| Защита от ссылки на удалённую запись | Только приложением | Ограничением БД |
| Защита от ссылки на несуществующий тип | Только приложением | По построению |
| Добавление новой сущности | Без миграции | Требует новой таблицы |
| Сложность выборок | Выше — фильтр по типу | Ниже |
| Соответствие лимиту 17 таблиц | **Да** | **Нет** — реестр вырос бы до 25 |

### 3.3. Рекомендация и признание риска

**Рекомендую полиморфную ссылку** для MVP.

**Обоснование:** явные таблицы связей увеличили бы реестр
с 17 до 25 таблиц — на 47%. Восемь дополнительных таблиц ради
ссылочной целостности одной технической сущности несоразмерны
задачам MVP.

**Признаю ослабление ссылочной целостности как осознанный риск:**

| Риск | Компенсирующая мера |
|---|---|
| Ссылка на удалённую запись | Физическое удаление запрещено — только архивирование |
| Ссылка на несуществующий тип | Перечень типов — системный классификатор с запретом изменения |
| Отсутствие каскадных проверок | Проверка целостности при архивировании целевой записи |

**Новых таблиц сверх 17 не добавляю.**

Формулировку «проверяется кворум» **снимаю** — без данных
о присутствии это невозможно.

> **Проверяется правоспособность списочного состава
> коллегиального органа. Фактическое наличие кворума
> на заседании системой MVP не рассчитывается.**

### 5.2. Что входит и не входит в MVP

| Функция | В MVP |
|---|---|
| Действующий списочный состав органа | **Да** |
| Наличие права голоса у участника | **Да** |
| Сопоставление числа членов с правом голоса и установленного кворума | **Да** — правоспособность состава |
| Индивидуальные голоса участников | **Нет** |
| Присутствие на заседании | **Нет** |
| Расчёт фактического кворума заседания | **Нет** |
| Подтверждение принятия коллегиального решения | **Протоколом или иным источником** через `source_usage` |

### 5.3. Взаимоисключающие ссылки участника

## 6. Уточнённое правило независимой проверки

### 6.1. Формулировка

> Пользователь не может подтверждать или утверждать запись,
> которую он создал либо содержательно изменил после последнего
> подтверждения, если для данного типа записи предусмотрена
> независимая проверка.

### 6.2. Сущности, требующие независимого подтверждения

| Сущность | Независимая проверка | Обоснование |
|---|---|---|
| `role_assignment` | **Да** | Наделение полномочием |
| `decision_participation` | **Да** | Определение права принимать решение |
| `decision_instance` | **Да** | Принятое управленческое решение |
| `collegial_body` | **Да** | Правоспособность органа |
| `collegial_body_member` | **Да** | Состав с правом голоса |
| `source_document` | **Да** | Основание полномочий |
| `initiative` | Нет | Описательная информация |
| `stakeholder` | Нет | Рабочие сведения |
| `person` | Нет | Справочная запись |
| `decision_type` | Нет | Настроечный шаблон |
| `decision_dependency` | Нет | Техническая связь |
| `source_usage` | Нет | Проверяется через документ |
| Справочники | Нет | Настройка |

### 6.3. Что считается содержательным изменением

| Изменение | Содержательное |
|---|---|
| Изменение субъекта полномочия (лицо, роль, орган) | **Да** |
| Изменение вида участия в решении | **Да** |
| Изменение принятого решения или его формулировки | **Да** |
| Изменение права голоса участника органа | **Да** |
| Изменение реквизитов документа-основания | **Да** |
| Изменение периода действия полномочия | **Да** |
| Исправление опечатки в описании | Нет |
| Изменение порядка сортировки | Нет |
| Добавление комментария | Нет |
| Обновление технических полей | Нет |

**Правило не распространяется автоматически на все технические
изменения.**

### 6.4. Сброс подтверждения

| Событие | Результат |
|---|---|
| Содержательное изменение подтверждённой записи | Статус **сбрасывается** в `needs_update`, требуется повторное подтверждение |
| Несодержательное изменение | Статус **сохраняется**, фиксируется в журнале |
| Изменение связанного документа-основания | Предупреждение по всем зависимым записям, статус не сбрасывается автоматически |

### 6.5. Отсутствие второго редактора

| Ситуация | Кто может подтвердить |
|---|---|
| В инициативе один редактор | **Управляющий кабинетом** |
| Управляющий кабинетом создал запись | Может подтвердить сам — вышестоящий проверяющий |
| Управляющий кабинетом отсутствует | Подтверждение **невозможно**, запись остаётся в статусе «на проверке» |

**Администратор подтверждать не может** — прав нет по матрице.

### 6.6. Аварийное исключение

| Параметр | Значение |
|---|---|
| Допускается | **Да**, как отдельное контролируемое действие |
| Кто может выполнить | **Только управляющий кабинетом** |
| Может ли администратор обойти правило по технической роли | **Нет** |
| Обязательное основание | Да, текстовое обоснование |
| Фиксация в журнале | Обязательна: кто, когда, какая запись, основание, что правило обойдено |
| Пометка записи | Запись помечается признаком «подтверждена в порядке исключения» |
| Отображение | Признак виден в интерфейсе и при экспорте |

**Администратор не обходит правило на основании технической
роли.** Это отдельное действие с основанием и журналированием,
доступное только управляющему кабинетом.

## 7. Нейтрализация классификаторов

### 7.1. «Вовлечённость» — переработан

**Признаю обоснованность замечания.** Прежний вариант — шкала
1–5 без формального расчёта — являлся субъективной
характеристикой человека. **Отменяю.**

**Новый классификатор `engagement_state` — проверяемые состояния:**

| Код | Состояние | Основание фиксации |
|---|---|---|
| `not_required` | Участие не требуется | Роль не предусмотрена в решениях инициативы |
| `invitation_not_sent` | Приглашение не направлено | Отсутствует запись о направлении |
| `invitation_sent` | Приглашение направлено | Есть запись с датой |
| `participation_confirmed` | Участие подтверждено | Есть подтверждение с датой |
| `materials_provided` | Материалы предоставлены | Есть ссылка на документ |
| `remarks_received` | Замечания получены | Есть зафиксированные замечания |
| `decision_pending` | Решение ожидается | Есть незакрытый экземпляр решения |
| `no_data` | Данные отсутствуют | **Явное состояние**, не заменяется предположением |

**Каждое состояние подтверждается записью в системе.**
Оценочных градаций нет.

### 7.2. «Состояние лица» — переработан

**Признаю обоснованность замечания.** Прежний вариант содержал
кадровые сведения: «в отпуске», «уволен», «переведён»,
«временно исполняет обязанности». Это персональные данные
о человеке, а не состояние записи. **Отменяю.**

**Новый классификатор `person_record_state` — служебные
состояния записи:**

| Код | Состояние | Смысл |
|---|---|---|
| `active` | Активно | Запись используется |
| `archived` | Архивировано | Выведена из обращения, история сохранена |
| `depersonalized` | Обезличено | Идентифицирующие сведения удалены, связи сохранены |

**Недопустимы:** медицинские, психологические, поведенческие
и любые оценочные состояния. Кадровые сведения — отпуск,
увольнение, перевод — в модели **не хранятся**.

### 7.3. Последствия переработки

| Что затронуто | Изменение |
|---|---|
| Матрица «формальное участие × вовлечённость» | Ось вовлечённости — **состояния**, не шкала 1–5 |
| Правило `W19` (лицо уволено, назначения активны) | **Отменено** — кадровые сведения не хранятся |
| Количество правил MVP | **17** вместо 18 |
| Количество классификаторов | **19** — без изменений |

### 7.4. Проверка остальных 17 классификаторов

| Классификатор | Нейтральность |
|---|---|
| Статус инициативы, этап, форма реализации | Состояния объекта |
| Тип роли | Функциональный признак |
| Уровень формального участия | Вычисляется из записей |
| Стратегия взаимодействия | Действие, не оценка |
| Уровень эскалации | Организационный уровень |
| Статус решения, статус исполнения | Состояния объекта |
| Тип источника | Признак документа |
| Роль в коллегиальном органе | Функциональный признак |
| Статус жизненного цикла, тип и происхождение | Состояния записи |
| Уровень уверенности | Свойство данных |
| Вид участия в решении | Функциональный признак |
| Уровень конфиденциальности | Свойство данных |
| Тип зависимости решений | Свойство связи |

**Оценочных характеристик человека не осталось ни в одном
из 19 классификаторов.**

## 8. Статус отключения архива

| Аспект | Статус |
|---|---|
| Отсутствие ветки выдачи | **Статически подтверждено** |
| Запрос без авторизации | **Фактически подтверждён** — 401 |
| Сохранность архива | **Подтверждена** контрольной суммой MD5 |
| Авторизованные сценарии | **Интеграционно не проверены** |
| Остаточный риск | **Принят** до появления изолированной среды |

**Изолированной тестовой среды нет.** Интеграционная проверка
не выполняется. Production-сессии не создаются, синтетические
роли в рабочей базе не заводятся, архивные данные не копируются,
рабочий эндпоинт дополнительными запросами не проверяется.

**Запрос на создание изолированной среды с синтетической базой**
может быть направлен владельцу платформы. Развёртывание такой
среды в разрешённый объём работ не входит.
