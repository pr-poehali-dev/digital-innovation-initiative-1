## 2. Правила действительности `source_usage`

Фиксация **концептуальная**. Ограничения, триггеры и переходы
статусов **не реализуются** без отдельного согласования.

### 2.1. Существующие ссылки — сохранность

| Правило | Формулировка |
|---|---|
| R01 | Архивирование целевой записи **не удаляет** `source_usage` |
| R02 | Архивирование `source_document` **не удаляет** его использования |
| R03 | Исторические связи сохраняются для аудита |
| R04 | Каскадное физическое удаление **не применяется** |
| R05 | Архивирование цели **не архивирует** документ автоматически |
| R06 | Архивирование документа **не архивирует** цель автоматически |
| R07 | Ссылка на архивированную, отменённую или логически удалённую запись **не считается «висячей»**, если физическая запись существует |

### 2.2. Новые ссылки — запрет по умолчанию

**По умолчанию запрещено** создавать новое `source_usage`:

| № | Условие запрета |
|---|---|
| Z01 | Целевая запись архивирована или логически удалена |
| Z02 | Документ архивирован, отменён или заменён |
| Z03 | Период применимости противоречит сроку действия документа |

### 2.3. Историческое уточнение — исключение из запрета

Допустимо **отдельное историческое уточнение**, если:

| Условие | Обязательность |
|---|---|
| Явно помечено как ретроспективная фиксация | Обязательно |
| Указан автор | Обязательно |
| Указана дата | Обязательно |
| Указано основание | Обязательно |
| Не возвращает архивированную запись в действующий оборот | Обязательно |
| Журналируется | Обязательно |

**Признак записи:** `is_retrospective = true`. Такая запись
**не участвует** в проверке актуальности оснований для
`confirmed` и `approved`.

### 2.4. Четыре различаемых понятия

Приняты как обязательные для разделения в модели:

| Понятие | Определение |
|---|---|
| **Физическое существование ссылки** | Строка `source_usage` существует в таблице |
| **Историческая действительность** | Ссылка была корректной на момент создания, сохраняется как факт истории |
| **Применимость на указанную дату** | `applicable_from` ≤ дата ≤ `applicable_to`, документ не отменён на эту дату |
| **Пригодность для текущего подтверждения** | Применимость **и** отсутствие архивирования/отмены **сейчас** |

**Все четыре понятия различны.** Физическое существование
не означает применимость; применимость в прошлом не означает
пригодность сейчас.

### 2.5. Потеря действующего основания

Если основание отменено, архивировано или утратило срок
действия:

| Правило | Формулировка |
|---|---|
| P01 | Зависимая запись **не удаляется** |
| P02 | Прежнее подтверждение **сохраняется в истории** |
| P03 | Запись **подлежит повторной оценке** |
| P04 | При потере актуального основания запись переводится в `needs_update` **либо** получает эквивалентный вычисляемый признак `basis_invalidated` до реализации переходов |
| P05 | **Новый** `confirmed` или `approved` на основании недействующего источника **невозможен** |

### 2.6. Замена документа

| Правило | Формулировка |
|---|---|
| S01 | Замена оформляется **новой карточкой** `source_document` |
| S02 | Замена оформляется **новым** `source_usage` |
| S03 | Старая карточка и использование **сохраняются как история** |
| S04 | Старая карточка получает состояние `заменён`, ссылается на новую |

### 2.7. Статус реализации

| Компонент | Статус |
|---|---|
| Правила R01–R07, Z01–Z03, P01–P05, S01–S04 | **Концептуально зафиксированы** |
| Ограничения базы данных | **Не реализованы** |
| Триггеры | **Не реализованы** |
| Автоматические переходы статусов | **Не реализованы** |
| Признак `is_retrospective` | Концептуальный, поля в БД нет |
| Признак `basis_invalidated` | Концептуальный, поля в БД нет |

**Реализация требует отдельного согласования.**

## 3. Право подтверждать собственные записи — окончательно

Правило независимости распространяется на **все системные
роли без исключения**.

| Правило | Формулировка |
|---|---|
| I01 | Создатель записи **не подтверждает** её независимо |
| I02 | Пользователь, содержательно изменивший запись после последнего подтверждения, **не подтверждает** её сам |
| I03 | Управляющий кабинетом **не считается независимым только из-за роли** |
| I04 | Администратор **не получает** содержательных прав из технической роли |
| I05 | Вышестоящее положение **само по себе не отменяет** правило независимости |

**Изменение зафиксировано окончательно:** прежнее допущение
о том, что управляющий кабинетом подтверждает собственные
записи как вышестоящий проверяющий, **отменено полностью**.

### 3.1. При отсутствии независимого проверяющего

Возможен только `accepted_by_exception`:

| Свойство | Значение |
|---|---|
| Равен `confirmed` | **Нет** |
| Считается независимой проверкой | **Нет** |
| Отображается как обычное подтверждение | **Нет** — отдельная пометка |
| Требует последующего контроля | **Да**, обязательно |

### 3.2. Исключение к собственной записи

| Правило | Формулировка |
|---|---|
| E01 | Допустимо **только как аварийная процедура** |
| E02 | Обязательно основание |
| E03 | Обязателен срок |
| E04 | Обязательна постановка в очередь ретроспективного контроля |

## 4. Просрочка исключения — вычисляемый признак `exception_expired`

Девятый статус **не вводится**. Статус `accepted_by_exception`
**формально сохраняется**, признак просрочки — отдельный.

### 4.1. Расчёт

| Параметр | Значение |
|---|---|
| Формула | `текущее время (UTC) > exception_expires_at` |
| Часовой пояс | **UTC**, однозначно, без исключений |
| Источник срока | Обязательное поле `exception_expires_at`, заполняется при установлении исключения |

### 4.2. Поведение после наступления срока

| № | Правило |
|---|---|
| X01 | Запись получает **явно видимый признак** `exception_expired` |
| X02 | Перестаёт считаться **действующей** по исключению |
| X03 | **Не учитывается** как подтверждённая или допустимая для операций, требующих актуального основания |
| X04 | Попадает в очередь контроля |
| X05 | **Не продлевается автоматически** |
| X06 | Требует **нового решения** с новым основанием и сроком, либо независимой проверки |

### 4.3. Досрочное прекращение

| Правило | Формулировка |
|---|---|
| X07 | Содержательное изменение прекращает действие исключения **досрочно**, независимо от указанного срока |
| X08 | История прежнего исключения **сохраняется** |

### 4.4. Отображение статуса с учётом просрочки

| Формальный статус в БД | Признак | Что видит пользователь |
|---|---|---|
| `accepted_by_exception` | Срок не наступил | «Принято по исключению до {дата}» |
| `accepted_by_exception` | `exception_expired = true` | **«Исключение истекло — требует решения»** |

### 5.2. `approved` — сохранение способа прохождения проверки

**Не должно скрывать способ прохождения проверки.**

| Поле | Назначение |
|---|---|
| `approved_via` | Значение: `confirmed` **или** `accepted_by_exception` |
| Обязательность | Заполняется при переходе в `approved` |
| Видимость | Отображается при просмотре истории записи |

| Путь к `approved` | Что сохраняется в `approved_via` |
|---|---|
| Независимое `confirmed` → `approved` | `confirmed` |
| `accepted_by_exception` → решение об использовании → `approved` | `accepted_by_exception`, с ссылкой на исключение |

**Утверждение никогда не выглядит одинаково независимо
от пути** — история прохождения проверки восстанавливаема.

## 7. Предохранитель тестов — двухэтапная модель

**Принимаю замечание.** Запрос `current_database()` требует
установленного сетевого соединения к базе — это сетевое
обращение. Прежняя формулировка «до первого сетевого запроса»
была неточной для этапа проверки базы. Разделяю на два этапа.

### 7.1. Этап 1 — до любого сетевого обращения

| Проверка | Источник | Сетевое обращение |
|---|---|---|
| `TEST_ENV_CONFIRMED == "isolated-test-env"` | Переменная окружения | **Нет** |
| `TEST_PROJECT_ID == "999001"` | Переменная окружения, локальное сравнение | **Нет** |

**При несовпадении — немедленный выход, без перехода к этапу 2.**

### 7.2. Этап 2 — только диагностическое подключение к базе

Выполняется **только если этап 1 пройден полностью**.

| Действие | Ограничение |
|---|---|
| Подключение к `TEST_DB_DSN` | **Единственное** разрешённое сетевое действие на этом этапе |
| Запрос | Только `SELECT current_database()` — диагностический, без записи |
| Проверка | Имя базы содержит маркер `test` **и** совпадает с ожидаемым |
| Таймаут подключения | 5 секунд |

**На этапе 2 запрещено:** HTTP-запросы к тестируемой функции,
создание пользователей, создание сессий, создание любых
фикстур, любая запись в базу.

### 7.3. Этап 3 — разрешается только после успеха этапов 1 и 2

| Действие | Условие разрешения |
|---|---|
| Прямая запись синтетических контекстов в базу | Только после подтверждения изолированной среды |
| Создание пользователей, сессий, синтетических данных | Только после подтверждения |
| HTTP-запросы к тестируемой функции | Только после подтверждения |

**И в любом случае — только в рамках будущего отдельного
разрешения на применение тестов.** Текущее разрешение
охватывает лишь подготовку и представление diff.

### 7.4. Обработка несовпадения на любом этапе

| Правило | Формулировка |
|---|---|
| F01 | Любое несовпадение → **немедленное завершение** |
| F02 | Завершение **без записи данных** |
| F03 | Завершение **до перехода к следующему этапу** |
| F04 | Код возврата — 2, сообщение перечисляет все несовпадения текущего этапа |

### 7.5. Изменённый псевдокод `conftest.py`

```python
# ПРОЕКТ. Иллюстрация трёхэтапной модели. Файл НЕ СОЗДАН.

def pytest_configure(config):
    # ── ЭТАП 1. Без сети ────────────────────────────────
    failures = []
    if os.environ.get("TEST_ENV_CONFIRMED") != "isolated-test-env":
        failures.append("TEST_ENV_CONFIRMED не подтверждён")
    if os.environ.get("TEST_PROJECT_ID") != "999001":
        failures.append("TEST_PROJECT_ID не подтверждён")
    if failures:
        pytest.exit("ОСТАНОВЛЕНО на этапе 1 (без сети):\n  - "
                    + "\n  - ".join(failures), returncode=2)

    # ── ЭТАП 2. ТОЛЬКО диагностика базы, без записи ────
    dsn = os.environ.get("TEST_DB_DSN", "")
    if not dsn:
        pytest.exit("ОСТАНОВЛЕНО: TEST_DB_DSN не задан",
                    returncode=2)
    try:
        with psycopg2.connect(dsn, connect_timeout=5) as conn:
            with conn.cursor() as cur:
                cur.execute("SELECT current_database()")  # только чтение
                dbname = cur.fetchone()[0]
    except Exception as exc:
        pytest.exit(f"ОСТАНОВЛЕНО на этапе 2: нет диагностического "
                    f"подключения к тестовой базе: {exc}",
                    returncode=2)
    if "test" not in dbname.lower():
        pytest.exit(f"ОСТАНОВЛЕНО на этапе 2: база '{dbname}' "
                    f"не помечена как тестовая", returncode=2)

    # ── ЭТАП 3. Разблокируется только здесь ────────────
    # Запись фикстур, HTTP-запросы — НЕ в pytest_configure,
    # а в отдельных фикстурах, выполняемых ПОСЛЕ этой точки.
```
